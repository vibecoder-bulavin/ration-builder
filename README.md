# Раціон під бюджет

Конструктор раціону під бюджет: форма (хто їсть, бюджет, магазини, що виключити) → раціон на тиждень (Економ / Оптимальний) → список покупок по магазинах і відділах.

## Як влаштовано

- `data/products.json` — 85 продуктів: КБЖУ, типова упаковка, правила пошуку в магазинах (`q`, `q2`, `inc`, `exc`).
- `data/recipes.json` — 94 страви з грамовкою на порцію.
- `data/sources.json` — міста, філії Сільпо, магазини zakaz.ua, філія Фори.
- `data/prices.json` — актуальні ціни (грн за 1 кг / 1 л / 1 шт), оновлюються щодня.
- `data/matches.json` — які саме товари обрано за останнім збором (для ручної перевірки).
- `data/history/` — ціни за кожен день.
- `collector/collect.mjs` — збір цін (Сільпо, zakaz.ua, Фора). Node 20, без залежностей.
- `site/template.html` + `site/build.mjs` — сайт збирається в `public/index.html`.

## Щоденне оновлення

GitHub Actions (`.github/workflows/collect-prices.yml`) щоночі запускає збір, комітить нові ціни, а Vercel бачить коміт і перезбирає сайт.

Захист від поганих даних:
- явні помилки збігу (ціна > 2,5× або < 0,35× медіани) відкидаються;
- якщо магазин сьогодні не віддав товар, лишається вчорашня ціна до 7 днів;
- якщо свіжих цін менше 30% від попередніх (схоже на блокування), `prices.json` не змінюється, а збір падає з помилкою.

Varus поки без автозбору: ціни внесені вручну 23–24.11.2026.

## Команди

```
node collector/collect.mjs --limit=3 --dry   # перевірити доступ до магазинів, нічого не записує
node collector/collect.mjs                   # повний збір (~20–30 хв)
node site/build.mjs                          # зібрати public/index.html
```

## Vercel

Імпортувати репозиторій у Vercel; налаштування беруться з `vercel.json` (build: `node site/build.mjs`, output: `public`).
